# 面向低资源葡萄牙语命名实体识别的 LLM 合成数据研究

项目书｜E0–E3 实验版本

## 一、数据集准备

### 1.1 数据选择与任务定义

项目从真实葡萄牙语 NER 数据出发，研究有限人工标注条件下，LLM 合成数据能否改善 GLiNER 的实体识别表现。葡萄牙语属于使用拉丁字母的非英语场景，项目不使用“非拉丁语系识别”这一表述。

当前对话尚未确定葡语数据集的具体版本。本版将 HAREM 作为优先核查的候选，而非已完成选择或已获取的数据。HAREM 是葡萄牙语实体识别评测资源，可从 [Linguateca HAREM 项目](https://www.linguateca.pt/HAREM/)核查原始材料；[SegundoHAREM 数据卡](https://huggingface.co/datasets/marquesafonso/SegundoHAREM)可用于了解相关分发版本。正式实施前必须核实原始来源、授权、标注版本、划分与转换规则。

旧参考方案中的 CrossNER 不直接沿用为本项目的葡语数据来源。未经单独设计和说明，不以机器翻译语料替代真实葡语测试集。

数据选择须满足：

- 文本为目标葡萄牙语，说明主要地区变体和文本领域。
- 有可核查的人工实体标注与明确的标签说明。
- 能提供至少 300 条真实训练样本，并另外保留独立开发集和测试集。
- 可恢复实体原文与位置，且许可允许本项目研究使用；向外部 LLM 提交种子前核查相应使用限制。

本项目默认“一条数据”为一句完整文本及其全部实体标注。若最终采用短段落作为单位，须在抽样、生成、统计和评测中统一，不能只比较样本条数而忽略文本长度差异。

### 1.2 数据划分

先划分真实数据，再抽取训练子集和生成种子。优先保留数据集官方划分；没有官方划分时，按文档或来源分组划分，固定随机种子并保存样本清单。禁止将同一文档的相邻句子随机分散到训练与测试两侧。

| 数据部分 | 数量要求 | 用途 |
|---|---|---|
| 真实训练池 | 至少可抽取 300 条 | 提供 E1 训练数据与生成种子 |
| E1 真实训练子集 | 300 条 | 真实监督训练参照 |
| 生成种子子集 | 20 条，来自上述 300 条 | E2/E3 共用的提示词示例与方法输入 |
| 开发集 | 依数据规模预先确定，记录实际数量 | 调试、阈值和检查点选择 |
| 测试集 | 依数据规模预先确定，记录实际数量 | 冻结方案后的最终评测 |

20 条种子属于训练数据，不是开发集或测试集。若目前总共只有 300 条真实标注，无法同时满足 E1 使用 300 条训练和独立开发/测试的要求，须另补评测数据或明确调整训练规模。

### 1.3 标签规范与预处理

先冻结标签集合、实体边界、嵌套/重叠处理、歧义实体处理及类别映射。最终标签以选定数据版本为准，不提前假定所有葡语语料都采用同一套类别。

保留原文、文档 ID 和原始标注；建立独立处理副本。统一 Unicode 处理和字符索引，使用左闭右开区间 `[start, end)`。每个实体满足 `text[start:end] == entity_text`。BIO 等输入格式转换后应检查标签连续性与可逆性；无法可靠转换的样本记录原因，不静默修复语义。

统一数据示例：

```json
{"id":"pt_0001","document_id":"doc_001","text":"Lisboa fica em Portugal.","entities":[{"start":0,"end":6,"text":"Lisboa","label":"LOC"},{"start":15,"end":23,"text":"Portugal","label":"LOC"}]}
```

示例中的 LOC 仅用于说明格式，正式类别以冻结的标签映射为准。训练适配时将字符区间转换为模型需要的 token 或 span 格式，验证转换后实体文本一致。

### 1.4 数据统计与质量核查

输出各集合的样本数、文档数、实体数、类别分布、平均文本长度、无实体样本比例、重复率和转换失败数。对 300 条真实子集及其中 20 条种子采用固定抽样策略，尽量覆盖主要类别并报告覆盖不足；不得查看测试表现后重新挑种子。

完成跨集合的完全重复和近重复检查。测试集检查由隔离的数据管理流程进行，仅向训练和生成侧返回排除标识，避免暴露测试文本和标签。

## 二、项目目标与研究问题

项目目标是在相同 GLiNER 起点和独立真实葡语测试集上，比较零样本推理、300 条真实数据微调、普通 LLM 合成数据微调以及 R-GDA 合成数据微调。

研究问题包括：

1. 300 条人工标注真实数据相较零样本推理能带来多少改善？
2. 仅提供 20 条真实示例时，300 条普通合成数据是否具有训练价值？
3. 在相同种子与最终合成数据规模下，完整 R-GDA 方法适配是否优于普通生成？其额外成本是多少？

本版本的研究贡献定位为葡语低资源场景下的受控方法比较与适配验证，不预设提出全新算法，也不保证某组一定取得最高 F1。

## 三、E0–E3 实验设计

| 实验 | 数据与处理 | 模型操作 | 作用 |
|---|---|---|---|
| E0 | 不使用任务训练样本 | 原始 GLiNER 直接推理 | 零样本基线 |
| E1 | 300 条人工标注真实训练数据 | 微调 GLiNER | 真实数据参照 |
| E2 | 相同 20 条真实示例提示 LLM，最终生成 300 条合成数据 | 微调 GLiNER | 普通合成数据基线 |
| E3 | 相同 20 条真实种子，经完整 R-GDA 方法适配，最终生成 300 条合成数据 | 微调 GLiNER | 反思式生成方法对照 |

主实验中 E2/E3 仅用各自 300 条合成数据微调，不额外混入 20 条真实种子；这些种子仅用于生成。若后续研究混合训练，应单列实验，两组采用完全一致的混合政策。

E1 和 E2/E3 的真实监督预算不同：前者可直接训练于 300 条真实标注，后两者生成时仅可访问 20 条。因此 E1 是参照，不能把它与合成组的差异解释成生成算法的纯因果效应。

## 四、模型与统一训练协议

选择支持目标语言的 GLiNER 预训练权重，先验证葡语推理与微调流程，再冻结模型名称、版本和权重标识。项目复用预训练模型，不从零预训练，不声称完整复现 GLiNER 的原始预训练实验。

E0–E3 共用相同初始权重、实体类别描述、文本截断和实体匹配规则。E1–E3 统一优化器、学习率政策、批大小、最大长度、训练预算和检查点选择规则。若训练样本长度差异明显，额外报告 token 数与实际更新步数。

正式训练前进行小规模运行，确定硬件可承受配置。显存不足时调整批量、梯度累积或精度，并将同一政策应用于所有微调组。具体数值在开发阶段确定后写入配置，不根据测试结果反复修改。

开发集可用于统一阈值和训练选择，但需记录使用范围。E0 是“不进行任务微调”的零样本模型；若阈值经开发集选择，应明确为开发集校准后的零样本评测。

## 五、E2：普通 LLM 合成数据生成

### 5.1 输入与提示词

输入固定 20 条真实文本及完整实体标注、标签定义、边界规范、目标葡语变体、领域范围和输出 Schema。普通生成不使用 R-GDA 的指导修炼与反思校准循环。

提示词要求生成新的自然文本，并标注所有符合规范的目标实体；避免照抄种子、机械替换实体及大量近重复句式。生成模型、提示词版本、温度、批量大小和随机参数必须留档。

### 5.2 生成与必要格式处理

分批生成并保存原始响应，直至获得最终 300 条可用于训练的合成样本。所有训练组采用统一的基本数据入口检查：JSON 可解析、标签合法、索引可对齐及完全重复检查。这是数据可加载性保障，不增加独立语义审核或根据 GLiNER 错误筛选样本的流程。

无歧义的格式转换可以自动完成；无法对齐的响应记录失败并补生成，不人工默默改标签。记录总候选数、有效数、失败数、重试数与费用。未被确定性检查发现的语义标注问题保留为普通生成的真实局限，并通过后续盲审估计。

## 六、E3：完整 R-GDA 方法适配

R-GDA 针对普通指导生成可能出现的过度抽象等问题，引入 Guidance Refiner（GR）与 Augmentation Calibrator（AC），分别检查指导和最终增强样本。方法背景参见 [R-GDA 原论文](https://aclanthology.org/2026.findings-eacl.259/)。

E3 的目标是保留论文完整方法结构，适配到葡萄牙语 NER、20 条种子、300 条最终合成数据和 GLiNER 下游评估。不得仅实现一次 LLM 质量打分后就称为完整 R-GDA。

### 6.1 实施流程

1. 使用与 E2 完全相同的 20 条真实种子及标签规范，构建论文规定的生成指导输入。
2. 执行指导生成/抽象步骤，保留其与种子、实体类型及领域要求的对应关系。
3. 执行 GR 对指导的反思与修改，按原方法的反馈循环和停止规则推进。
4. 使用修炼后的指导生成葡语增强文本与实体标注。
5. 执行 AC 对增强结果的领域适配性与标签完整性校准，按原方法反馈、修改与停止。
6. 将方法输出转为统一格式，通过与 E2 相同的基本入口检查；补足最终 300 条训练数据。
7. 保存指导、各轮反馈、修改版本、终止原因、最终样本与成本。

### 6.2 复现边界与实现验收

正式运行前通读原论文及可获得的官方实现，建立“论文环节—实现位置—原参数—项目参数—适配原因”对照表。具体评分阈值、反馈轮数、角色提示词与停止条件以核查后的实现配置为准，不在未核对时凭经验填入并称为原论文设定。

角色调用可在同一程序中编排，不要求使用多个自治软件代理；关键是保留原方法规定的角色、信息流与反馈机制。若某环节无法实现，必须显式列为偏差并调整方法名称和结论，不宣称完整适配已达成。

本项目不沿用原论文的全部数据集、数据量和下游模型，因此结果是葡语场景下的方法适配验证，不是原论文实验成绩复现。

## 七、实验控制与数据泄漏防护

- E2/E3 使用相同种子、生成基础模型版本、标签规范、语言及领域范围；额外角色调用与反馈成本属于 E3 方法差异，单独记录。
- E2/E3 最终均为 300 条合成数据；相同条数不代表相同生成成本、文本长度或实体数量，均需报告。
- 生成、指导修炼和校准流程均不能访问 E1 子集中未被选为种子的其余 280 条标注。
- 测试文本、标签及其错误分布不得进入提示词、反馈或样本选择。开发集不作为补充生成示例。
- 所有方法共用标签映射、训练入口检查、测试集与评测程序。不得对某组追加人工语义修正而不披露。
- 保存数据哈希、配置、提示词、响应与训练种子，确保结果可追溯。记录测试集可能与预训练语料重合的不可完全排除风险。

## 八、评价与结果分析

### 8.1 下游 NER 指标

主指标为严格实体级 Micro-F1：预测实体的起止位置和类型均正确才计为正确实体。同步报告 Precision、Recall、Macro-F1、各类别 F1 和真实实体支持数，明确 Macro-F1 的类别集合及零分母处理规则。

建议微调组至少使用 3 个配对训练随机种子，报告均值、标准差和差值。配对置信区间按文档重采样；仅重复训练无法覆盖合成数据生成的不确定性，资源允许时另做独立生成重复。

### 8.2 关键比较

| 比较 | 回答的问题 | 解释边界 |
|---|---|---|
| E1 − E0 | 真实数据微调的收益 | 反映监督训练价值 |
| E2 − E0 | 普通合成数据能否改善零样本表现 | 包含微调与合成监督的共同作用 |
| E3 − E2 | 完整 R-GDA 适配是否优于普通生成 | 同时报告额外调用与费用 |
| E2/E3 与 E1 | 合成训练相对真实训练的表现 | 不能忽略真实标注预算差异 |

### 8.3 合成数据质量与成本

从 E2/E3 最终数据中按同一规则随机抽样，进行隐藏方法来源的人工盲审，检查类别、边界、遗漏、伪实体、语言自然度与重复情况。记录抽样规模、分母和仲裁规范。质量盲审用于分析，不将发现的修正反馈回主实验训练数据；若要修正须单列实验。

报告生成总样本数、最终收率、平均文本长度、每条实体数、类别覆盖、重复率、调用次数、Token、费用及耗时。不能仅凭 LLM 自评分或更高数据质量评分推断下游 F1 必然提高。

### 8.4 可选补充实验

在主实验完成后，可单独考察 20 条真实种子直接微调、合成数据量变化、多个种子子集，以及固定费用下的 E2/E3 比较。这些属于补充研究，不改变 E0–E3 主实验定义。没有开展 GR/AC 消融时，不把整体提升归因于其中某一个角色。

| 阶段 | 主要工作 | 验收产物 |
|---|---|---|
| 1. 数据冻结 | 来源与授权核查、格式转换、划分、抽样 | 数据说明、划分清单、300/20 条样本 ID、统计表 |
| 2. 模型打通 | 推理、微调小规模运行、评测校验 | 可运行配置、E0 结果、格式转换检查记录 |
| 3. 真实基线 | E1 多种子训练 | 模型检查点、训练日志、开发集结果 |
| 4. 普通生成 | E2 生成 300 条并训练 | 原始响应、最终 JSONL、成本与模型结果 |

```text
project/
  data_manifest/        # 来源、授权、样本 ID、哈希及划分
  data/processed/       # 真实数据的独立处理副本
  data/synthetic/e2/    # 原始响应与最终 300 条

  configs/             # 模型、训练、生成、评测配置

```

最终交付包括：一套冻结的数据处理与划分方案、E0–E3 可复现实验配置、两组合成训练数据、微调模型、逐样本测试预测、严格实体评测结果、R-GDA 方法适配对照表、成本与质量分析，以及研究报告。公开数据或模型时遵守来源许可与隐私限制。

## 十一、风险与预期成果

主要风险包括少量种子覆盖不足、合成文本模板化、类别分布偏移、R-GDA 在新语言领域迁移效果有限、训练随机性及额外调用费用。通过冻结种子、报告分布、人工盲审、配对训练和成本统计控制解释范围。

项目预期产出是对“20 条种子能否支持有用的葡语 NER 合成训练”和“完整 R-GDA 适配相对普通生成是否值得”给出可复核的实证回答。负结果同样应完整报告，不以未经验证的性能提升、算法创新或论文完全复现作为预设结论。
