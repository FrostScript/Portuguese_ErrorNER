# 09 实验运行记录

**状态：** 已定
**相关：** `docs/runs/`、`docs/logs/project_log.md`

## 1. 规则

**每跑完一次实验，在 `docs/runs/` 下新建一个 Markdown 文件**，文件名：

```
YYYY-MM-DD_<实验标识>_<数据划分>.md
例：2026-11-04_E0_zeroshot_dev.md
```

一次实验一个文件；同一实验重跑就是新文件（加 `_v2` 后缀），**不覆盖、不追加到同一个文件**。

## 2. 必须包含的内容

### 2.1 运行配置（缺一不可）

| 项 | 说明 |
|---|---|
| 实验标识 | E0 / E1 / E2 / E3 / pilot / 消融 |
| 数据 | 文件路径 + 句子数 + 文档数 + 实体数 |
| 模型 | 名称 + 本地路径 + 大小（微调组还要写初始 checkpoint 与种子） |
| 脚本 | 完整相对路径 |
| **完整命令** | 可直接复制执行的命令行 |
| 超参 / 阈值 | 学习率、步数、batch、阈值网格、bootstrap 次数与随机种子 |
| 环境 | Python / torch / transformers / gliner 版本，HF 镜像，临时目录 |

### 2.2 产物

列出输出文件的绝对路径（报告、JSON、缓存、checkpoint）。

### 2.3 结果

主表 + 分类别指标 + 错误结构 + 置信区间 + 耗时。数字必须是**跑出来的**，不得手填估计值。

### 2.4 观察与后续动作

- 观察：本次跑出来的、值得记的现象，含反常现象；
- 后续动作：触发了哪些 TODO 编号。

## 3. 与其他文档的分工

| 位置 | 记什么 |
|---|---|
| `docs/runs/*.md` | **单次实验**的完整快照（配置 + 结果） |
| `docs/logs/project_log.md` | **任务级**摘要：做了什么、关键数字、改了哪些文件、遗留问题 |
| `docs/specs/*.md` | **规范**：该怎么跑 |
| `docs/TODO.md` | **未完成事项**与待决策 |

三者不互相替代；实验文件里不写规范条文，只引用规范文件名。

## 4. 追溯要求

报告中引用的每个数字，必须能在 `docs/runs/` 里找到对应的文件与命令。找不到来源的数字不得进入最终报告。

## 5. 文档维护约定（2026-11-04）

**`README.md` 由 AI 维护。** 每次结构性改动（新增/删除文件、目录变化、约定变更、结论更新）后自动同步根目录 README，不需逐次确认。

分工：

| 位置 | 记什么 | 谁维护 |
|---|---|---|
| `README.md` | 全局导航：目录说明、数据流、关键约定、环境坑 | AI，自动同步 |
| `docs/specs/` | 实现依据（该怎么跑） | 决策变更时同步 |
| `docs/runs/` | 单次实验快照（跑了什么、结果如何） | 每次实验后新建 |
| `docs/logs/project_log.md` | 任务级变更摘要 | 每个任务后追加 |
| `docs/TODO.md` | 未完成事项与待决策 | 状态变化时更新 |
