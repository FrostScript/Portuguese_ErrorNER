# 02 数据划分与泄漏防护

**状态：** 部分已定；dev 的二次切分尚未实施（TODO C3）
**相关：** 项目书 §1.2 / §7、修订 V2.0 §3、§7

## 1. 主划分（已定）

保留 UNER 官方划分，不重新切句：

| 用途 | 来源 | 规模 |
|---|---|---:|
| 训练池 | `train` | 7,018 句 / 235 文档 |
| 开发池 | `dev` | 1,172 句 / 41 文档 |
| 测试 | `test` | 1,167 句 / 40 文档 |

**禁止**把同一文档的句子分散到训练与测试两侧。官方划分本身是文档级的（train 235 篇、dev 41 篇、test 40 篇互斥），已满足，不需重切。

## 2. dev 的二次切分：已取消（2026-11-04）

**决定：dev 不切分，完整 1,172 句 / 40 篇同时用于"选 checkpoint"和"报告指标"。**

取消理由：

1. 原设计里 **Dev Feedback（300 句）只服务于已删除的 Error-Aware 实验**（算类别 Recall 调生成配额），E0–E3 方案没有这个需求；
2. **Dev Selection 的"搜阈值"用途也消失**——阈值已统一固定为 0.80，不再逐组搜索；
3. 剩下的用途只有"选 checkpoint"，用完整 dev 就够；
4. 继续切会把报告集从 1,172 句缩到 300 句（约 10 篇文档），实测 CI 宽度 0.067 会扩大到约 0.13，把统计功效白扔掉。

**代价与披露：** dev 兼作模型选择与报告集，存在轻微乐观偏差。必须在 limitations 中写明，并在报告中说明"没有独立的第三份数据用于模型选择"。

**仍保留的清单要求（必须做）：** 三集文档级清单落盘，用于泄漏审计与复现。

| 产物 | 内容 |
|---|---|
| `data/pt_bosque/split_manifest.json` | 每集的句子/实体/文档数、文档 ID 列表、每篇句数、文件 sha256、跨集交叠检查 |
| `data/pt_bosque/split_manifest.md` | 同上的人读版本 |
| 脚本 | `src/data/make_split_manifest.py` |

**文档 ID 命名空间（重要）：** 原始 iob2 里每个 split 的文档编号各自从 `batch-0000` 开始，跨集必然重名。因此 `prepare_uner.py` 给 doc_id 加了 split 前缀，形如 `dev:batch-0000`。不这么做，跨集泄漏审计会误报"全部文档交叠"。

**实测审计结果：** train&dev / train&test / dev&test 的文档交叠均为 **0**。

## 3. E1 训练集抽样（已定：2026-11-04）

**口径：随机口径 + 45% 无实体句**，与 E2/E3 的合成数据配比一致。

| 项 | 值 |
|---|---|
| 来源 | `data/pt_bosque/train.jsonl` |
| 规模 | 300 句 = **135 无实体句（45%）+ 165 含实体句** |
| 抽样 | 无实体句随机抽；含实体句先保证三类各 ≥ 30 mention，再随机补足；随机种子 **42** |
| 去重 | 剔除 train 内部完全重复 11 条、与 dev/test 完全重复 3 条 |
| 存放 | **`data/curated/real_300.jsonl`**（单独存放，便于复现） |
| 清单 | `data/curated/real_300_manifest.json`（种子、ID 清单、源文件与输出 sha256） |
| 统计 | `data/curated/real_300_stats.md` |
| 脚本 | `src/data/make_real_300.py` |

实测结果：300 句 / 167 文档 / 376 实体（PER 134、ORG 113、LOC 129）/ 7,861 token；含实体句平均 2.28 个实体。

**硬约束：**
- 该文件是 E1 的唯一训练数据来源，不得临时换数据重抽；
- 20 条生成种子（TODO A6）从这 300 条中选取，不另抽；
- 若必须重抽，种子与脚本参数要改版本号（如 `real_300_v2.jsonl`），旧文件保留。

## 4. 泄漏防护（已定）

1. **Test 只用一次**：正式评测在方案冻结后执行，评测前不得查看 test 的模型输出。
2. **Test 不得进入**：Prompt、示例、反馈、样本筛选、超参调整、错误画像。
3. **生成侧可见信息**：只允许训练池的原始文本与 20 条种子（含标注）；不得访问 dev / test 的任何标注。
4. **种子来源**：20 条种子必须取自已确定的 E1 训练集（300 条的子集），不得取自 dev 或 test。
5. **重复检查**：已知 train&test 1 条、train&dev 2 条完全重复句，Phase 1 从 train 侧剔除。
6. **近重复检查**：生成前计算 train（含风格参考池）与 test 的 8-gram 重叠，剔除训练侧重复。
7. **风格参考池**（若启用）：只提供原始文本，不提供任何标注。

报告中必须给出：三个 split 的样本数与文档数、dev 二次切分的两份清单、被剔除的重复句清单、种子 20 条的 ID 列表。
