# 04 生成约束（句长、实体密度、模板化）

**状态：** 已定；数值待生成后实测校准
**相关：** 修订 V2.0 §4 N1、§5 Y2

## 1. 为什么要约束

真实数据的分布是：

| 指标 | train | dev | test |
|---|---:|---:|---:|
| Token/句 | 24.48 | 24.27 | 23.65 |
| 实体/句（全体句） | 1.154 | 1.195 | 1.041 |
| 实体/句（仅含实体句） | 2.08 | 2.13 | 1.95 |

若合成句平均 40 token、3 个实体，则"300 条"口径下 E2/E3 的实体监督量约为 E1 的 2 倍以上，等量对比失效。**所以句长与密度是约束项，不是报告项。**

## 2. 硬约束（写入 Prompt + 校验器）

| 约束 | 值 | 校验方式 |
|---|---|---|
| 每句词数 | **17–30 个空格切分的词**，目标 ~22 | 按空白分词计数 |
| 每句实体数（含实体句） | **1–5**，多数 1–3 | 以 `entities` 长度为准 |
| 每句实体数（全体句） | 目标均值 ~1.25 | 与无实体句比例联动，见 05 |
| 标签覆盖 | 三类都必须出现 | 统计 per-class 计数 |
| 实体边界 | 多词实体完整 | 校验 `text[start:end] == ent` |

### 2.1 为什么是 17–30 个词，而不是 20–30 个 token

真实数据的 24.48 是 **UD token**（`de o`、`a as` 这类被 UD 拆开的成分算两个 token）。合成文本没有 UD 分词，只能用**空格切词**计数，两者实测比值 **空格词 / UD token = 0.861**：

| 口径 | 20 条种子实测 |
|---|---|
| UD token | 范围 20–30，均值 25.2 |
| 空格词数 | 范围 **15–28**，均值 21.8 |

若沿用 20–30 个空格词，等于要求 UD 口径 24–36 token，比种子分布更长，会把最短的那批自然句直接判掉。因此改为 **17–30 空格词**（下界对齐种子最短句，上界留少量余量）。

### 2.2 为什么实体数上界是 5 而不是 3

E1 真实数据 165 条含实体句中，实体数分布为 `1:70 / 2:44 / 3:26 / 4:11 / 5:7 / 6:2 / 7:3 / 8:1 / 20:1`——**15% 的句子有 4 个以上实体**。上界取 3 会让合成数据的实体密度系统性低于 E1，与 `specs/05` 的对齐目标相反。故取 5，覆盖 E1 的 95%（163/165）。

20 条种子本身也印证了这点：实体数 1–5，其中 4 条超过 3。

## 3. 内容约束

1. 自然、连贯的葡萄牙语（巴西葡语为主）；
2. 模仿葡语新闻语体，**不得照抄**参考文本或 20 条种子；
3. 只使用 PER / ORG / LOC 三类标签；
4. 标注句中**所有**符合规范的目标实体（不漏标）；
5. 不得生成仅替换实体名的模板化句式；
6. 结构化输出（JSON），带 `text` + `entities[{start,end,text,label}]`。

## 4. 模板化度量（生成后必算）

| 指标 | 定义 | 用途 |
|---|---|---|
| 与种子 n-gram 重叠 | 生成句与 20 条种子的 4-gram / 8-gram 最大重叠率分布 | 判断是否照抄 |
| 实体复用率 | 生成样本中的实体串有多少来自种子实体集合 | 判断是否只是换壳 |
| 句式重复率 | 生成样本两两之间（去实体后词序）的重复比例 | 判断是否模板化 |

三个指标写入质量报告。E2 与 E3 必须用同一套方法计算，便于对比。

**风险提示：** 20 条种子生成 300 条是 15 倍放大，而 R-GDA 原论文的动机正是"GDA 容易过度抽象、句子缺少领域词汇"。若 E2 的模板重复率显著高于 E3，E3 的优势必须打折解释（它可能只是在修复种子过少造成的缺陷）。

## 5. 长度分布一致性

生成完成后对比"含实体句"与"无实体句"的长度分布（均值、中位数、标准差）。二者出现系统性差异时，说明生成器在"写空句"时切换了语体，需重写 Prompt 或重采样。**这是防止负样本规范引入新混杂变量的检查项。**

### 5.1 已知风险：无实体批次没有真实范例（2026-11-04 记录，待试产验证）

`seeds_20` 的 20 条种子**全部含实体**（选出时要求"必须含实体"以示范标注格式）。因此 `e2_negative` / `e3_negative` 两个模板拿到的是 20 个带实体的样例，却被要求产出零实体句——**只能靠文字指令，没有范例可参照**。

可能后果：

- 语体漂移：为避开专名而写得干瘪、空泛，与含实体批次风格分叉；
- 与 §5 的长度分布一致性要求相冲突。

**决策（2026-11-04）：暂不改模板**，留到 G4 试产时人工评估。试产必须逐条判断：

| 检查项 | 判据 |
|---|---|
| 无实体句是否被"挖空" | 主语完整、语义连贯，不像删掉了名字 |
| 语体是否与含实体批一致 | 同一体裁（新闻）、相近长度 |
| 是否写得过于空泛 | 有具体信息（数字、时间、机构职能泛称） |

若三项中任一不过，再补"从 `real_300` 的 135 条真实无实体句中取 3 条作为 `{NO_ENTITY_EXAMPLES}` 注入"的方案。

## 6. 记录要求

每次生成必须落盘：模型名与版本、Prompt 版本号、温度与采样参数、批次大小、生成时间、token 用量、费用、候选数 / 有效数 / 失败数 / 重试数。

### 6.1 已定参数（2026-11-04）

| 项 | 值 |
|---|---|
| 生成模型 | **DeepSeek Flash**（固定版本，全程不换；换模型则整批数据作废） |
| 模板集 | `prompts/templates/`（用户提供的模板版 + 3 个无实体变体，共 8 个 stage） |
| **E2 与 E3 共用同一套模板** | 差别只在 E3 多 guidance → refiner 两个前置步骤 |
| 模板机制 | 占位符 `{LABEL_SCHEMA}` `{SEED_EXAMPLES}` `{N}` `{BATCH_ID}`（E3 另有三个），由 `prepare_prompt.py` 运行时注入，不预填 |
| 输入示例 | `prompts/templates/data/seeds_20.json`（与 `data/curated/seeds_20.jsonl` 同一批 20 条，**已核实 20/20 一致**） |
| 每批结构 | 20 条 = 11 含实体（`e2_generation`）+ 9 无实体（`e2_negative`），**两次独立请求** |
| 输出格式 | **JSONL**，一行一条：`{"id","text","entities":[{"text","label","occurrence"}]}` |
| 温度 | 0.8（试产确认后冻结） |
| 批次 ID | 形如 `e2_001` / `e2_101`（含实体 / 无实体用不同号段），**不得重复** |

**关键设计一：模型不输出字符下标。** 只给实体文本 + `occurrence`，由 `convert_validate.py` 定位计算 `[start, end)`。见 `specs/03` §6。

**关键设计二：两阶段校验，职责不重叠。**

| 阶段 | 脚本 | 管什么 |
|---|---|---|
| ① 格式与偏移 | `prompts/templates/convert_validate.py` | ID/文本唯一、occurrence 定位、区间不重叠、E3 的 keep/revise/reject；失败则整批不写出 |
| ② 项目规范 | `src/generate/validator.py` | 句长 20–30、实体数 ≤3、抄种子与 8-gram、跨批重复、无实体句比例统计 |

`convert_validate.py` 新增 `--expect {auto,entity,none}`：含实体批次用 `entity`，无实体批次用 `none`；不指定时沿用原严格规则（必须有实体）。**一次调用只能处理同类批次**，混批会被整批拒绝。

### 6.2 八个 stage 与各自的校验模式

| stage | 用在哪 | 条数/批 | 校验模式 |
|---|---|---:|---|
| `e2_generation` | E2 含实体 | 11 | `--expect entity` |
| `e2_negative` | E2 无实体 | 9 | `--expect none` |
| `e3_guidance` | E3 第 1 步：初始指导 | — | 人工/后续步骤使用 |
| `e3_refiner` | E3 第 2 步：审查优化指导 | — | 同上 |
| `e3_generation` | E3 含实体 | 11 | `--expect entity` |
| `e3_negative` | E3 无实体（沿用同一 refined guidance） | 9 | `--expect none` |
| `e3_calibrator` | E3 校准含实体批 | — | `--expect entity` |
| `e3_calibrator_negative` | E3 校准无实体批 | — | `--expect none` |

E3 的无实体批次切在 `e3_generation` 之后、沿用同一份 refined guidance，保证两类句子的语体与主题分布一致。

**实体种子来源：** 不另建实体清单。20 条种子自带的 45 个实体（PER 17 / ORG 18 / LOC 10）即 Prompt 的实体示例来源，可追溯至 UNER `pt_bosque` train。
