# 04 生成约束（句长、实体密度、模板化）

**状态：** 已定；数值待生成后实测校准
**相关：** 修订 V2.0 §4 N1、§5 Y2

## 1. 为什么要约束

真实数据的分布是：

| 指标 | train | dev | test |
|---|---:|---:|---:|
| Token/句 | 24.48 | 24.27 | 23.65 |
| 实体/句（全体句） | 1.154 | 1.195 | 1.041 |
| 实体/句（仅含实体句） | 2.08 | 2.13 | 1.95 |

若合成句平均 40 token、3 个实体，则"300 条"口径下 E2/E3 的实体监督量约为 E1 的 2 倍以上，等量对比失效。**所以句长与密度是约束项，不是报告项。**

## 2. 硬约束（写入 Prompt + 校验器）

| 约束 | 值 | 校验方式 |
|---|---|---|
| 每句 token 数 | 20–30，目标 24 | 按空格切分后计数 |
| 每句实体数（含实体句） | 1–3，目标均值 2.08 | 以 `ner` 数组长度为准 |
| 每句实体数（全体句） | 目标均值 1.15 | 与无实体句比例联动，见 05 |
| 标签覆盖 | 三类都必须出现 | 统计 per-class 计数 |
| 实体边界 | 多词实体完整 | 校验 `text[start:end] == ent` |

## 3. 内容约束

1. 自然、连贯的葡萄牙语（巴西葡语为主）；
2. 模仿葡语新闻语体，**不得照抄**参考文本或 20 条种子；
3. 只使用 PER / ORG / LOC 三类标签；
4. 标注句中**所有**符合规范的目标实体（不漏标）；
5. 不得生成仅替换实体名的模板化句式；
6. 结构化输出（JSON），带 `text` + `entities[{start,end,text,label}]`。

## 4. 模板化度量（生成后必算）

| 指标 | 定义 | 用途 |
|---|---|---|
| 与种子 n-gram 重叠 | 生成句与 20 条种子的 4-gram / 8-gram 最大重叠率分布 | 判断是否照抄 |
| 实体复用率 | 生成样本中的实体串有多少来自种子实体集合 | 判断是否只是换壳 |
| 句式重复率 | 生成样本两两之间（去实体后词序）的重复比例 | 判断是否模板化 |

三个指标写入质量报告。E2 与 E3 必须用同一套方法计算，便于对比。

**风险提示：** 20 条种子生成 300 条是 15 倍放大，而 R-GDA 原论文的动机正是"GDA 容易过度抽象、句子缺少领域词汇"。若 E2 的模板重复率显著高于 E3，E3 的优势必须打折解释（它可能只是在修复种子过少造成的缺陷）。

## 5. 长度分布一致性

生成完成后对比"含实体句"与"无实体句"的长度分布（均值、中位数、标准差）。二者出现系统性差异时，说明生成器在"写空句"时切换了语体，需重写 Prompt 或重采样。**这是防止负样本规范引入新混杂变量的检查项。**

## 6. 记录要求

每次生成必须落盘：模型名与版本、Prompt 版本号、温度与采样参数、批次大小、生成时间、token 用量、费用、候选数 / 有效数 / 失败数 / 重试数。

### 6.1 已定参数（2026-11-04）

| 项 | 值 |
|---|---|
| 生成模型 | **DeepSeek Flash**（固定版本，全程不换；换模型则整批数据作废） |
| 模板集 | `prompts/templates/`（你提供的模板版，5 个模板 + 新增 1 个无实体变体） |
| 模板机制 | 占位符 `{LABEL_SCHEMA}` `{SEED_EXAMPLES}` `{N}` `{BATCH_ID}`（E3 另有三个），由 `prepare_prompt.py` 运行时注入，不预填 |
| 输入示例 | `prompts/templates/data/seeds_20.json`（与 `data/curated/seeds_20.jsonl` 同一批 20 条，**已核实 20/20 一致**） |
| 每批结构 | 20 条 = 11 含实体（`e2_generation`）+ 9 无实体（`e2_negative`），**两次独立请求** |
| 输出格式 | **JSONL**，一行一条：`{"id","text","entities":[{"text","label","occurrence"}]}` |
| 温度 | 0.8（试产确认后冻结） |
| 批次 ID | 形如 `e2_001` / `e2_101`（含实体 / 无实体用不同号段），**不得重复** |

**关键设计一：模型不输出字符下标。** 只给实体文本 + `occurrence`，由 `convert_validate.py` 定位计算 `[start, end)`。见 `specs/03` §6。

**关键设计二：两阶段校验，职责不重叠。**

| 阶段 | 脚本 | 管什么 |
|---|---|---|
| ① 格式与偏移 | `prompts/templates/convert_validate.py` | ID/文本唯一、occurrence 定位、区间不重叠、E3 的 keep/revise/reject；失败则整批不写出 |
| ② 项目规范 | `src/generate/validator.py` | 句长 20–30、实体数 ≤3、抄种子与 8-gram、跨批重复、无实体句比例统计 |

`convert_validate.py` 新增 `--expect {auto,entity,none}`：含实体批次用 `entity`，无实体批次用 `none`；不指定时沿用原严格规则（必须有实体）。**一次调用只能处理同类批次**，混批会被整批拒绝。

**实体种子来源：** 不另建实体清单。20 条种子自带的 45 个实体（PER 17 / ORG 18 / LOC 10）即 Prompt 的实体示例来源，可追溯至 UNER `pt_bosque` train。
