# 07 评测协议

**状态：** 已定
**相关：** 项目书 §8、修订 V2.0 §4 D2/D4、§5 N1

## 1. 主指标

**严格实体级 Micro-F1**：预测实体的**起始位置、结束位置、类别**三者全对才计为 True Positive。部分重叠不计分。

同步报告：Precision、Recall、Macro-F1、各类别 P/R/F1、各类别真实实体支持数。

## 2. 阈值：全项目统一 0.80（2026-11-04 决策，取代逐组搜索）

GLiNER 用单一概率阈值判定实体；微调后分数分布会整体偏移，阈值不控住就无法比较。

| 项 | 定 |
|---|---|
| **统一阈值** | **0.80**，E0 / E1 / E2 / E3 全部使用 |
| 搜索集 | 无（不再逐组搜索）；E0 在完整 dev 上的 17 档扫描仅作为选阈值的依据 |
| 网格（仅参考） | 0.10–0.90，步长 0.05 |
| 每次评测仍输出 | 完整 17 档扫描表，扫描最优值记入 `experiments.csv` 的 `notes` 列 |
| 记录 | 主表必须写明所用阈值（恒为 0.80） |

**决策依据：** E0 在 dev 上扫描最优恰为 0.80（Micro-F1 0.7497），且 0.75 / 0.80 / 0.85 分别为 0.7442 / 0.7497 / 0.7427，区间平坦、不是尖峰，因此固定 0.80 不会偏袒任何一组。

**已知代价（必须在报告中披露）：** 微调后模型分数整体上移，0.80 对它们未必最优。扫描表的"最优阈值 F1"作为敏感性分析一并报告，但**不进主表、不用于挑选**，避免出现"各组选各自最优"的不可比局面。

**实现优化（已定）：** 不做"每档阈值跑一次推理"。用 `threshold=0.0` 一次性拿到每句全部候选 span 与分数，落盘缓存，再离线扫网格——缓存可跨 arm 复用，换阈值零成本。

## 3. 指标定义

| 指标 | 定义 |
|---|---|
| Micro P/R/F1 | 跨三类合并统计 TP/FP/FN 后计算 |
| Macro F1 | 三类 F1 的算术平均，类别集合 = 冻结的 3 类 |
| Per-class F1 | 逐类计算，附支持数 |
| False Negative Rate | FN / (TP + FN) |
| **Type Error** | 边界正确但类别错误 |
| **Boundary Error** | 类别正确但边界不完全一致 |
| 零分母处理 | 报告必须写明；某类支持数 < 20 时显式标注"该类别 F1 不可解释" |

## 4. 置信区间

- **bootstrap**：对测试集的**文档**做重采样（40 篇文档），1,000 次，报 Micro-F1 的 95% 置信区间；
- 微调组用 3 个配对训练种子，报均值与标准差，同时报配对差值；
- 说明限制：重复训练无法覆盖**合成数据生成**本身的不确定性（见 `04`/`05` 的生成侧方差）。

## 5. 主表结构

| Method | 真实标注量 | 生成成本 | 阈值 | P | R | Micro-F1 | 95% CI | Macro-F1 | 无实体句比例 | 实体/句 | token/句 |
|---|---|---|---|---|---|---|---|---|---|---|---|

"真实标注量"列：E0 = 0，E1 = 300，E2/E3 = 20（仅生成用）。这一列是解释边界的核心，不可省略。

## 6. 比较与解释边界

| 比较 | 回答 | 不得声称 |
|---|---|---|
| E1 − E0 | 真实标注微调的收益 | — |
| E2 − E0 | 合成数据能否改善零样本 | 不能归因为"合成数据本身"，含微调效应 |
| E3 − E2 | 完整 R-GDA 是否优于普通生成 | 不能分解为"反思机制"的单独贡献（含成本效应） |
| E2/E3 vs E1 | 合成相对真实的表现 | 不能忽略真实标注预算差异（300 vs 20） |

## 7. 一致性要求

- 所有 arm 使用同一评测脚本、同一匹配规则、同一测试集；
- 测试集**只评一次**，方案冻结后执行；
- 任何 arm 的预测结果不得人工修正；若修正必须整组重跑并声明。
