# 葡萄牙语 NER：E0–E3 实验报告

**数据集：** `pt_bosque`（UniversalNER / Portuguese-Bosque UD）
**基座模型：** GLiNER `gliner_multi-v2.1`（零样本起点，四个 arm 同一初始化）
**评测集：** dev，1,172 句 / 40 篇文档 / 1,401 实体
**统一阈值：** 0.80（所有 arm 固定，不逐组搜索）
**报告日期：** 2026-11-13

---

## 摘要

在同一基座、同一评测协议下比较四种训练数据来源：零样本（E0）、300 条真实句（E1）、300 条 LLM 合成句（E2）、300 条经 R-GDA 适配流程生成的合成句（E3）。

- **合成数据能显著提升零样本基线**，但**无法追上同等规模的真实数据**。E2/E3 的最优成绩（0.8030 / 0.8006）比 E1（0.8487）低约 4.6–4.8 点。
- **R-GDA 适配的主要收益是稳定性，不是峰值**：E3 在 100/200/500 三档预算下的成绩浮动只有 1.9 点，而 E2 浮动 3.6 点、E1 浮动 9.3 点；E3 在 S=500 不再出现过拟合。
- **训练预算决定了"合成 vs 真实"的胜负**：低预算（S=100/200）下合成数据领先，高预算（S=500）下真实数据反超 5.0–8.2 点。
- **ORG 始终是最弱类别**，三层数据依次为 0.6561 → 0.7047 → 0.7383，合成数据只部分缓解。

---

## 一、研究问题

1. 300 条真实标注数据能把零样本 GLiNER 提升多少？
2. 用 LLM 生成的 300 条同规模合成数据，能否替代真实数据？
3. 在生成流程中加入 R-GDA（Guidance Refinement + Augmentation Calibration）能否让合成数据的质量进一步接近真实数据？

---

## 二、实验设置

### 2.1 数据

| 数据 | 来源 | 规模 | 构成 |
|---|---|---|---|
| E1 训练集 | `pt_bosque` train 抽样 | 300 句 | 165 含实体 + 135 无实体，376 实体（PER 134 / ORG 113 / LOC 129），覆盖 167 篇 |
| E2 训练集 | DeepSeek Flash 零样本生成 | 300 句 | 165 含实体 + 135 无实体，413 实体（124 / 146 / 143） |
| E3 训练集 | R-GDA 流程生成 | 300 句 | 165 含实体 + 135 无实体，451 实体（PER 139 / ORG 163 / LOC 149） |

三者同标签规范（PER / ORG / LOC）、同正负配比。E1 与 E2/E3 使用同一批 20 条种子句（`seeds_20.jsonl`，45 个实体，全部来自 train 侧）。

### 2.2 训练协议

batch 2，lr 2e-5，步数 ∈ {100, 200, 500}，种子 ∈ {13, 23, 33}；每个 arm 9 组，共 27 组。所有 arm 从同一预训练权重独立初始化，不续训。

### 2.3 评测协议

严格实体级匹配（span + label 全对），固定阈值 0.80，报告 Micro-F1 / Macro-F1 / 分类别 F1 / 错误分类 / bootstrap 95% CI。阈值 0.80 是在 dev 上一次性确定的协议常量，不再逐组搜索；每次评测仍输出 17 档扫描表作为敏感性分析。

### 2.4 E3 方法说明（重要偏离）

R-GDA 原论文的 AC 阶段是**四项打分（30/30/25/15，满分 100）**，阈值 90。本项目 2026-11-10 起**改为无评分判定**：AC 不再打分，只对每条样本给出 `keep / revise / reject` 三态，用具体问题驱动修订，最多 3 轮，未通过复检的样本丢弃。

偏离理由：smoke 实测 AC 均分 97.6–100、零 reject，100 分制已无区分度。**代价**：本组实验不得报告"AC 平均分"，对外表述限定为「R-GDA 适配，AC 判定改为问题驱动」。GR 侧仍严格保留论文的 100 分制、五项权重与 90 分阈值。

## 四、分析

### 4.1 预算效应：合成数据的优势只存在于低预算区间

E2 在 S=100 / 200 时比 E1 高 1.5 / 0.7 点，到 S=500 反而低 8.2 点；E2 的训练 loss 在 500 步降到 0.58（E1 为 1.87），说明 300 条合成句被记住而非泛化。E3 经过校准后压住了这个趋势：S=500 时比 E2 高 3.2 点，与 E1 的差距从 8.2 点收窄到 5.0 点。

**推论：**"合成数据能否替代真实数据"没有单一答案，取决于训练预算。任何跨 arm 比较都必须同时给出同预算与各自最优两列。

### 4.2 R-GDA 的收益是稳定性，不是峰值

| arm | 三档预算均值 | 极差 |
|---|---:|---:|
| E1 | 0.8002 | 9.3 点 |
| E2 | 0.7802 | 3.6 点 |
| **E3** | **0.7938** | **1.9 点** |

E3 的最优值（0.8006 @S=100）与 E2 的最优值（0.8030 @S=200）只差 0.24 点，统计上不可区分；但 E3 用 **1/2 的训练步数**达到同等水平，且对步数选择不敏感——这在工程上意味着可以省掉调步数的试错。

### 4.3 精度—召回结构

E2 普遍低精度（0.72–0.79）高召回，即模型"更敢报"、误报多；E1 在 S=500 时精度 0.8093 仍保持召回 0.8922。E3 的精度（0.7718–0.7973）介于两者之间且更平稳，说明 AC 的逐条驳回确实过滤掉了一部分不可靠样本，但没能恢复真实数据的精度水平。

### 4.4 ORG 是共同瓶颈

| arm | PER | ORG | LOC |
|---|---:|---:|---:|
| E0 | 0.8360 | 0.6561 | 0.7141 |
| E1 @500 | 0.9340 | 0.7383 | 0.8527 |
| E2 @200 | 0.8968 | 0.7047 | 0.7945 |
| E3 @100 | 0.9076 | 0.6903 | 0.7856 |

ORG 始终比 PER 低 20 点以上。合成数据对 ORG 的提升（+4.9 点）小于对 LOC 的提升（+8.0 点）；E3 相对 E2 在 ORG 上甚至略降。**下一阶段若继续做数据增强，ORG 应是唯一优先目标。**

## 五、需要披露的问题

### 5.1 E3 生成阶段的复现材料缺失

E3 的 300 条正式数据（`formal-300-20261110_170725`）的原始轨迹——`gr_trace.json`、`e3_summary.json`、`state.json` 以及 73 次请求的 raw response——**不在当前工作机磁盘上**，本地 `D:\pt_ner_work\data\synthetic\e3\` 只有 2026-11-05 的 20 条 smoke 产物。

数据本身已逐条校验（300 行、165/135、451 实体、span 与 `text[start:end]` 全部自洽、token 与原文一致、无重复句），但**生成过程不可复现**。此外该数据的 id 形态（`e3_pos_001_001`）与当前 HEAD 的脚本批次前缀（`e3_0`/`e3_1`）不一致，提示正式那批并非由当前版本脚本直接产出。

对结论的影响：**训练与评测不受影响**（只读 `text`/`entities`），但报告中不得声称 E3 生成链路完整可复现。

### 5.2 E3 @S=200 的种子异常

`seed=23, S=200` 得 0.7376，明显低于同组（0.8030 / 0.8049），也低于该种子在 S=100（0.7959）与 S=500（0.8001）的成绩——非单调。该点把 E3 @S=200 的标准差抬到 0.0383。引用 E3 @S=200 时应单列说明，或只引用 @S=100。

### 5.3 阈值与选择的既定语料偏差

- 阈值 0.80 是在 dev 上选定的，dev 同时承担"选 checkpoint"与"报告"两个角色，存在乐观偏差；
- 各 arm 的"最优步数"同样在 dev 上选出；
- 上述两项均需在 test 上一次性确认，不得在 test 上调参。

### 5.4 G4 人工验收未闭环

E2 的 9 条无实体句仍需人工确认（非"挖空"残缺句、语体一致、不空泛）。E3 无实体句同样适用该验收。

## 六、结论

1. **300 条真实数据是最强杠杆**：0.7497 → 0.8487（+9.9 点），且 CI 不重叠。
2. **同规模合成数据在低预算下可用，高预算下失效**：E2 最优 0.8030 出现在 S=200，S=500 已过拟合到 0.7667。
3. **R-GDA 适配让合成数据对预算不敏感**：三档预算极差 1.9 点，S=500 不再掉点，但峰值未突破（0.8006）。
4. **当前证据不支持"合成数据替代真实数据"**，只支持"合成数据在低预算下性价比更高"。
5. **ORG 是三类中唯一始终未被拉上来的**，与数据来源无关，可能与类别定义边界和上下文稀疏有关。
