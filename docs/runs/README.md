# 实验运行记录

**规则：** 每跑完一次实验，在本目录新建**一个** Markdown 文件，文件名 `YYYY-MM-DD_<实验名>_<数据划分>.md`，内容固定包含两大部分：**运行配置**与**结果**。

## 为什么单独建文件

- 一次实验一个文件，便于横向对比、便于回溯"这个数字是哪次跑出来的"；
- 不覆盖、不追加，跑重了就是新文件（文件名加序号，如 `..._v2.md`）；
- 汇总性的结论才写进 `docs/logs/project_log.md`，这里只放单次实验的完整快照。

## 固定结构

| 段落 | 必须写清 |
|---|---|
| 元信息 | 日期、实验名（E0/E1/E2/E3/pilot 等）、状态（成功/失败/部分） |
| 运行配置 | 模型（名称+本地路径+大小）、数据（文件+句子数+文档数）、脚本路径、**完整命令**、超参/阈值网格、随机种子、环境版本 |
| 产物 | 输出文件的绝对路径 |
| 结果 | 主表、分类别指标、错误结构、置信区间、耗时 |
| 观察 | 这次跑出来的、值得记的现象（含反常现象） |
| 后续动作 | 这次结果触发的 TODO 条目编号 |

## 与规范的关系

本目录记录"跑出来什么"，`docs/specs/` 定义"该怎么跑"，`docs/logs/project_log.md` 记录"做了什么改动"。三者不互相替代。
