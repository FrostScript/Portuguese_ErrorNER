# 2. 已核实事实

## 2.1 候选数据集规格对照

这是本轮最关键的事实表：新项目书把数据源列为"待核查候选"，而三个候选的真实规格差异极大。

| 项 | UNER `pt_bosque` | `Linguateca/harem`（官方上传） | `marquesafonso/SegundoHAREM` |
|---|---|---|---|
| 葡语变体 | 巴西葡语 | 欧洲葡语为主，含多种体裁 | 欧洲葡语 |
| 划分 | **7,018 / 1,172 / 1,167 句** | **121 / 8 / 128 文档** | **129 文档，无划分** |
| 划分层级 | 句级 | 文档级 | 无 |
| 语料规模 | 171,776 / 28,447 / 27,604 token | HAREM 约 93k 词；miniHAREM 约 65k 词（作 test） | 129 篇，总量约 1.8 MB 序列化 |
| 实体数 | 8,101 / 1,401 / 1,215 | 卡片未给 | 卡片未给 |
| 实体密度 | 1.154 / 1.195 / 1.041 实体每句 | 需实测 | 需实测 |
| 句长 | 24.5 / 24.3 / 23.7 token 每句 | 需实测（新闻段落，明显更长） | 需实测 |
| 标签集 | PER / ORG / LOC（3 类，IOB2） | **10 类**（PESSOA, ORGANIZACAO, LOCAL, TEMPO, VALOR, ABSTRACCAO, ACONTECIMENTO, COISA, OBRA, OUTRO）；`selective` 配置 5 类 | 5 类 / 10 类两版（`selective` / `total`） |
| 标注层级 | 单一类别 | 原资源有 Category + Sub-type 两层，HF 版本**只用 Category** | 同左 |
| 许可 | **CC-BY-SA-4.0** | **unknown** | MIT（第三方再许可，非原始授权） |
| 标注者 | 母语志愿者（UNER 项目） | expert-generated | 转自 Linguateca |
| 本机可得性 | 一条 `load_dataset` + 镜像即可 | 同左，但需核实授权 | 同左，但无划分 |
| 是否满足项目书 §1.1 | ✓ 全部满足 | 训练量够；**验证集仅 8 篇**；标签 10 类 | **无划分，需自切 129 篇**；标签 5/10 类 |

**三条硬伤（针对新项目书 §1.1 的"至少 300 条真实训练样本 + 独立开发集和测试集"）：**

**H1 — 验证集只有 8 篇文档。** `Linguateca/harem` 的 validation 为 8 篇，而开发集在新项目书中承担三件事：阈值搜索、checkpoint 选择、生成侧配额统计。8 篇（按新闻篇幅估约 200–300 句）比 V1.0 设计的 872 条小一个数量级，阈值选择会极不稳定。

**H2 — 10 类标签遇 20 条种子，长尾类别必死。** ABSTRACCAO / OBRA / COISA / OUTRO 在 20 条种子里大概只能出现 0–2 次，模型对这些类的 F1 趋近 0，Macro-F1 会被零分母支配。新项目书 §8.1 只说"明确零分母处理规则"，但问题不在规则，在**类别集合本身没有被裁剪**。

**H3 — 许可未定，卡住项目书自己写的规则。** 官方卡片标注 `license: unknown`；第三方 `SegundoHAREM` 标为 MIT 属再许可行为，不能作为原始授权依据。项目书 §1.1 要求"许可允许本项目研究使用"，这一条目前无法签署。

## 2.2 R-GDA 论文核实结果

| 项 | 值 |
|---|---|
| 标题 | R-GDA: Reflective Guidance Data Augmentation with Multi-Agent Feedback for Domain-Specific Named Entity Recognition |
| 作者 | Hyeonseok Kang, Hyuk Namgoong, Goun Pyeon, Sangkeun Jung |
| 出处 | Findings of EACL 2026, pp. 4938–4953, Rabat, Morocco |
| DOI | 10.18653/v1/2026.findings-eacl.259 |
| 两个 agent | Guidance Refiner（GR，评估初始抽象、抑制过度泛化）、Augmentation Calibrator（AC，校验最终样本的领域保真与标签完整性） |
| 原论文实验场景 | SciERC、NCBI-disease、FIN —— **英文科学与生物医学领域** |
| 原论文结论 | 在 SciERC 与 NCBI-disease 提升 F1，多数情况下 BERTScore 更低（句子更多样）；FIN 上与 GDA 基线相当 |

**由此得到的适配难度：** 把该迁移到葡语新闻 NER，等于同时跨越 **语言（英→葡）+ 领域（生物医学/科学→新闻）+ 标签集（领域标签→PER/ORG/LOC）** 三重边界。新项目书 §6.2 的自我约束（拿不到实现细节必须改方法名称、不得宣称完整适配）写得正确，但**没有做成闸门**，见 §5 Y3。

# 3. 数据决策

## 3.1 推荐：`pt_bosque` 做主数据，HAREM 做补充

| 理由 | 说明 |
|---|---|
| 规格已知 | 句子/实体/token 数、实体密度、句长全部实测过，可以立刻设计等量对照 |
| 划分官方 | 句级 train/dev/test，不需要自己切，也不存在切分泄漏风险 |
| 许可明确 | CC-BY-SA-4.0，可签署项目书 §1.1 的授权要求 |
| 标签贴合 | 3 类正好对应 PER/ORG/LOC，20 条种子的类别覆盖可控 |
| 成本 | 一条 `load_dataset` 即可开始，Phase 1 可当天完成 |

HAREM 的价值不在替代，在**补充**：欧洲葡语变体 + 不同体裁，可作为"结论是否只在巴西葡语成立"的旁证实验（属于主实验之后的补充，不改变 E0–E3 定义）。

## 3.2 若坚持 HAREM 主线，必须同时做四件事

| 编号 | 动作 |
|---|---|
| H1-修 | 从 121 篇训练文档中按**文档级**再划出 Dev（建议 20 篇），与原 8 篇验证集合并使用；划分清单落盘 |
| H2-修 | **冻结标签集**：只保留 PESSOA / ORGANIZACAO / LOCAL 三类（或 selective 版的 5 类），其余类明确排除，写入标签映射表；Macro-F1 的类别集合 = 冻结后的集合 |
| H3-修 | 向 Linguateca 核实原始授权并留存证据（邮件/页面存档）；在报告中写明数据来源、版本与授权状态 |

# 4. 仍生效的硬约束（新项目书尚未落实）

## D1-S — 固定优化步数 S，并规定 S 的确定方法

新项目书 §4 写了"统一训练预算"，但没有说 S 怎么定。同一数据量下步数过多会过拟合、过少会欠拟合，而 E1（300 条真实）与 E2/E3（300 条合成）的合适步数未必相同。

**规定：** Phase 3 用 1 个种子做 pilot，扫 `S ∈ {100, 200, 300, 500}` 步，取"E1 与 E2 的 Dev Micro-F1 均未出现连续两个评估点下降"的最大 S，写入配置后冻结，全部可训练组使用同一 S 与同一 batch。

## D6 — 候选池与接受率对齐

新项目书 §5.2 对四组使用统一的**入口检查**，但 E3 有 GR/AC 过滤会丢弃样本，E2 只有格式检查，两者接受率必然不同，导致"最终 300 条"背后消耗的候选数与成本差数倍。

**规定：** 记录并报告每组的 `候选数 / 有效数 / 失败数 / 重试数 / token / 费用`；主表并列一行"每条有效样本的平均成本"。不做对齐就会让 Y1 的成本混杂无解。

## N1 — 句长与实体密度必须约束，不是只报告

新项目书 §7 写"相同条数不代表相同文本长度或实体数量，均需报告"——只是披露，没有约束。若合成句平均 3 个实体、40 token，则 E2/E3 在"300 条"口径下拿到的实体监督量约为 E1（300 条 × 1.15 ≈ 345 个）的 2 倍以上，等量对比失效。

**规定：**
- 以 Phase 1 统计出的真实分布为基准（若用 `pt_bosque`：每句 20–30 token、1–3 实体、均值 1.2）；
- 生成 Prompt 写死该区间，校验器硬过滤；
- 主表附列每组的"实体/句、token/句、实体总数、token 总数"。

## N2 — 输出目录必须落 D 盘

C 盘剩 33.4 GB，checkpoint + 候选池 + 原始响应 + 缓存会写满，中断点难以回滚。

**规定：** 输出根目录 `D:\pt_ner_work\`；C 盘只留 `src/`、`configs/`、`prompts/`、`data_manifest/`、少量切分后数据。

## N3 — HF 下载走镜像

`huggingface.co` 被 DNS 污染不可达。

**规定：** 全局设置 `HF_ENDPOINT=https://hf-mirror.com` 后再下载权重与数据集；镜像地址写入 `configs/` 与 README。

## N4 — 质量判定阈值必须在试产阶段冻结

新项目书 §6.2 要求"以核查后的实现配置为准，不凭经验填入"，方向对，但缺一个明确的冻结动作与时点。若在生产 300 条上边筛边调，等于让 E3 自己挑样本。

**规定：** GR/AC 的评分阈值、反馈轮数上限、停止条件，只在 Phase 4 的 30–50 条试产样本上确定，写入 `configs/rgda.yaml` 后冻结；Phase 5 只执行不修改，如确需修改必须整组重跑并记录。

# 5. 新增条款（E0–E3 结构下特有）

## Y1 — E3 − E2 混入了成本效应（最高优先级）

**问题：** E3 完整 R-GDA = GR 多轮 + AC 多轮 + 两个角色 + 数倍 token；E2 只有一次生成。E3 − E2 的差值 = 反思机制的收益 **+** 数倍调用预算的收益。

**后果：** 主结论"完整 R-GDA 适配相对普通生成是否值得"无法回答，因为"值不值得"本身包含成本，而成本没有被控制住。

**修法（二选一，必须在 Phase 4 之前定）：**

| 方案 | 内容 | 代价 |
|---|---|---|
| **成本匹配对照（推荐）** | 新增 **E2+**：给 E2 与 E3 相同的 token/调用预算，做多候选普通生成后取 300 条 | 多一组生成 + 多一组训练（3 种子约 3.3 GB） |
| 成本效应显式声明 | 不做 E2+，但在主表与结论中标注"E3 的收益包含未分解的成本效应" | 无额外成本，但结论强度下降 |

新项目书 §8.4 把"固定费用下的 E2/E3 比较"列为**可选补充**，本文建议升为必做或必须声明。

## Y2 — 模板化风险必须量化

**问题：** 20 条种子生成 300 条 = 15 倍放大，句式与实体高度复用。而 R-GDA 的原动机正是"GDA 容易过度抽象、句子缺少领域词汇"——因此 E3 的一部分提升可能只是在修复 20 条种子人为造成的缺陷。

**修法：** Phase 5 对 E2 与 E3 各算三个指标，进质量报告：

| 指标 | 定义 |
|---|---|
| 与种子的 n-gram 重叠 | 生成句与 20 条种子的 4-gram / 8-gram 最大重叠率分布 |
| 实体复用率 | 生成样本中出现的实体串有多少来自种子的实体集合 |
| 模板重复率 | 生成样本两两之间的句法骨架（去实体后的词序）重复比例 |

若 E2 的模板重复率显著高于 E3，E3 的优势必须打折解释。

## Y3 — R-GDA 适配入口闸门

**问题：** 三重迁移 + 可能不存在的官方实现。新项目书 §6.2 写了要求，但没有设卡点。

**规定：** Phase 5 开工前必须先产出对照表，列 `论文环节 | 原参数 | 本项目参数 | 实现位置 | 适配原因`，且至少覆盖 GR 的评分标准、AC 的校验维度、反馈轮数、停止条件四项。**四项中任一项无法从论文或公开实现中确认，方法名称降级为 "R-GDA-inspired"，报告中不得出现"完整适配"表述。**

## Y4 — 标签集与长尾裁剪

**规定：** Phase 1 冻结标签集（建议 3 类：PESSOA/ORGANIZACAO/LOCAL，即 PER/ORG/LOC），写出完整映射表与排除清单。§8.1 的 Macro-F1 类别集合等于冻结后的集合，并逐类报告真实实体支持数。若某类在 300 条训练集中的 mention 数 < 20，在报告中显式标注"该类的 F1 不可解释"。

## Y5 — 开发集的规模下限

**规定：** 开发集必须满足"≥ 100 句且每类 mention ≥ 30"，否则阈值搜索与 checkpoint 选择的方差会超过待测效应。若所选数据集（如 `Linguateca/harem`）达不到，按 §3.2 的 H1-修 从训练池按文档级补划。

## Y6 — 贡献定位需确认（非技术项）

删除 Error-Aware 后，项目从"提出机制"变为"葡语场景下的受控方法比较与适配验证"，新项目书 §2 已诚实说明"不预设提出全新算法"。若课程/评分标准要求明确 contribution，需在报告引言中显式重述贡献为：

1. 把 R-GDA 从英文生物医学域适配到葡语新闻域，并给出完整的适配偏差清单；
2. 在等量真实监督（300 条）与等量种子（20 条）条件下给出 E0–E3 的受控比较；
3. 给出合成数据的成本—质量—下游 F1 三角关系，包括负结果。
